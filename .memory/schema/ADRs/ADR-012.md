# ADR-012: Ether Refactor Medio (Opción B) — Migración DSOL → Ether

## Estado
**Implementado** — El monolito `lib/dsol.py` fue refactorizado al paquete `lib/ether/` con 6 módulos especializados. `lib/dsol.py` se mantiene como fachada backward-compatible que re-exporta de `lib.ether/`.

## Contexto

DSOL (`_scripts/lib/dsol.py`) era un monolito de 807 líneas con score de calidad 53/100 que mezclaba 7 responsabilidades distintas. Era el punto único de routing multi-modelo, tracking de tokens, circuit breaking, rate limiting, cache optimization y API client para DeepSeek. Fue renombrado a **Ether** (Environment for Token Harmonization & Execution Regulation) para reflejar que ya no optimiza solo para DeepSeek, sino que ruthea entre 3 modelos (Flash, Pro, Kimi) vía OpenCode Go.

### Problemas identificados (pre-refactor)

1. **Baja cohesión** (score 35/100): 7 responsabilidades en un solo archivo
2. **Duplicación de lógica**: CircuitBreaker existía tanto en `dsol.py` (líneas 191-235) como en `cost_optimizer.py` (líneas 107-131)
3. **Alto acoplamiento** (score 65/100): consumidores como `lib/llm.py`, `lib/orchestrator.py`, `lib/dashboard.py` importaban directamente del monolito
4. **Baja testeabilidad** (score 40/100): 807 líneas dificultaban mocking y tests unitarios aislados
5. **Mantenibilidad reducida** (score 50/100): modificaciones en una funcionalidad podían romper otras no relacionadas

### Opciones consideradas

| Opción | Descripción | Esfuerzo | Score post | Riesgo |
|--------|------------|----------|-----------|--------|
| **A** (Mínimo) | Renombrar clases, agregar docstrings | 1d | 60 | Bajo |
| **B** (Medio) | **6 módulos separados + fachada** | **6d** | **75-82** | **Medio** |
| C (Máximo) | Reescribir completo con nueva arquitectura | 15d | 90+ | Alto |

**Opción seleccionada: B (Medio).** Balance óptimo entre mejora de calidad y riesgo de regresión. Se implementó como `lib/ether/` en lugar de `lib/dsol/` para reflejar el cambio de alcance (multi-modelo, no solo DeepSeek).

## Decisión

### Arquitectura Implementada

Se dividió `dsol.py` en un paquete `lib/ether/` con 6 módulos especializados. `lib/dsol.py` se mantiene como fachada backward-compatible:

```
lib/
├── dsol.py                  ← Fachada backward-compatible [DEPRECATED v1]
│                              Re-exporta de lib.ether. Emite DeprecationWarning.
│                              Se eliminará en KAOS v3.0.
└── ether/
    ├── __init__.py           ← Re-exportaciones públicas
    ├── config.py             ← BUDGETS, THINKING_CONFIG, MODEL_TIERS,
    │                            TASK_MODEL_MAP, AGENT_DEFAULT_TASK,
    │                            MODEL_FALLBACK_CHAIN, DEEPSEEK_API_URL
    ├── circuit.py            ← CircuitBreaker unificado (fusión dsol + cost_opt)
    ├── limiter.py            ← RateLimiter, check_rate_limit
    ├── tracker.py            ← EtherTracker (thread-safe, atomic writes),
    │                            extract_cache_metrics, _calc_cost, reset_tracker
    ├── client.py             ← call_api, chat, call_structured, generate_structured,
    │                            build_prompt, build_optimized_context,
    │                            estimate_cache_ratio, configure_thinking, allocate,
    │                            get_output_config
    ├── router.py             ← resolve_model, _resolve_fallback,
    │                            _ETHER_CIRCUIT_BREAKER
    ├── observability.py      ← Métricas y observabilidad
    ├── judge/                ← Evaluación de calidad (DeepEval)
    └── eval/                 ← Evaluaciones de output
```

### APIs Públicas Preservadas

La fachada `dsol.py` re-exporta todas las funciones y clases desde `lib.ether`:
- `resolve_model(task_type, agent, model_override)`
- `chat(task_type, messages, agent, model, thinking, temperature, max_tokens)`
- `call_api(prompt, model, thinking, use_json, task_type, max_retries)`
- `status()` — CLI status
- `EtherTracker` — clase (antes TokenTracker)
- `CircuitBreaker` — clase
- `_ETHER_CIRCUIT_BREAKER` — instancia singleton

## Consecuencias

### Positivas
+ Cohesión: 35 → 85 (cada módulo tiene una responsabilidad única)
+ Acoplamiento: 65 → 80 (fachada desacopla consumidores)
+ Testeabilidad: 40 → 90 (módulos aislados < 200 líneas)
+ Mantenibilidad: 50 → 85
+ CircuitBreaker unificado elimina duplicación (ver ADR-013)
+ Thread safety: EtherTracker usa threading.Lock y atomic writes
+ Preservación total de APIs públicas — fachada dsol.py mantiene compatibilidad

### Negativas
- Esfuerzo de 6 días calendario requerido para la migración
- Riesgo de regresión durante WP5-WP6 (migración de lógica crítica)
- Solapamiento temporal: dsol.py fachada y ether/ coexisten durante migración
- Import circular potencial entre módulos (mitigado por fachada)

## Riesgos

| Riesgo | Prob | Impacto | Score | Mitigación |
|--------|------|---------|-------|------------|
| Regresión en routing | Media | Alto | 15 | Test suite en WP9 + smoke test post-WP7 |
| Import circular | Baja | Medio | 6 | Fachada como único punto de entrada externo |
| Coexistencia dsol.py+ether/ | Alta | Medio | 8 | WP8 elimina imports legacy; duración limitada |
| cost_optimizer.CircuitBreaker legacy | Media | Bajo | 4 | ADR-013 define migración; deprecación gradual |
