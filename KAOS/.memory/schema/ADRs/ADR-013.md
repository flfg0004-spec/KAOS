# ADR-013: CircuitBreaker Unificado

## Estado
**Implementado** — CircuitBreaker unificado implementado en `lib/ether/circuit.py` como `_ETHER_CIRCUIT_BREAKER`. Re-exportado por `lib/dsol.py` como `_CIRCUIT_BREAKER` para backward compatibility.

## Contexto

Existían **dos implementaciones de CircuitBreaker** en el códigobase:

### CircuitBreaker A: `lib/dsol.py` → `lib/ether/circuit.py`

```python
class CircuitBreaker:
    """Circuit breaker por modelo — evita llamar modelos que fallan repetidamente."""
    
    def __init__(self, failure_threshold=3, reset_timeout=300, half_open_max=1):
        ...
    def is_available(self, model: str) -> bool: ...
    def record_success(self, model: str): ...
    def record_failure(self, model: str): ...
    def get_status(self) -> dict: ...
```

- **Singleton**: `_ETHER_CIRCUIT_BREAKER = CircuitBreaker()` (en ether/circuit.py)
- **Per-model**: trackea fallos por modelo (`go-flash`, `go-pro`, `go-kimi-latest`)
- **Estados**: closed → open → half-open → closed
- **Uso**: `resolve_model()` verifica antes de usar un modelo; fallback si está abierto
- **Uso en chat()**: registra success/failure después de cada llamada vía `agent_llm_call`

### CircuitBreaker B: `lib/cost_optimizer.py` (líneas 107-131)

```python
class CircuitBreaker:
    def __init__(self, failure_threshold: int = 3, reset_timeout: int = 300):
        ...
    def record_failure(self): ...
    def record_success(self): ...
    def is_open(self) -> bool: ...
    def state(self) -> str: ...
```

- **Per-provider**: trackea fallos por proveedor (`deepseek`, `opencode-go`)
- **Almacenamiento**: persistido en `cost_optimizer.json` dentro de `_state["breaker_states"]`
- **Uso**: `provider_available()` en `lib/llm.py` verifica antes de llamar al provider
- **Wrapper funcional**: `record_provider_result()`, `provider_available()`, `get_breaker()`

### Problemas de la duplicación

1. **Dos fuentes de verdad diferentes**: `_ETHER_CIRCUIT_BREAKER` en ether/circuit.py vs `_breakers` dict en cost_optimizer.py
2. **Semántica inconsistente**: Ether usa per-model, cost_opt usa per-provider
3. **Lógica duplicada**: Ambos implementan failure_threshold + reset_timeout con diferencias sutiles (half-open vs simple time-window)
4. **Mantenimiento duplicado**: Cambios en la lógica de circuit breaking requieren modificar 2 archivos
5. **Testing duplicado**: Tests en `test_ether_router.py` y `test_cost_optimizer.py` prueban la misma funcionalidad con diferente semántica
6. **Dashboard inconsistente**: `dashboard.py` no refleja el estado de ambos breakers

## Decisión

**Fusionar ambas implementaciones en un único `CircuitBreaker` ubicado en `lib/ether/circuit.py`** (como parte del refactor ADR-012, WP2). La fachada `lib/dsol.py` re-exporta el breaker como `_CIRCUIT_BREAKER` para backward compatibility.

### Diseño del CircuitBreaker Unificado

```python
class CircuitBreaker:
    """Circuit breaker unificado — soporta per-model y per-provider.
    
    Reemplaza:
    - dsol.CircuitBreaker (lib/dsol.py) → lib/ether/circuit.py
    - cost_optimizer.CircuitBreaker (lib/cost_optimizer.py)
    """
    
    FAILURE_THRESHOLD_DEFAULT = 3
    RESET_TIMEOUT_DEFAULT = 300  # 5 minutos
    HALF_OPEN_MAX_DEFAULT = 1
    
    def __init__(self, ...):
        ...
    
    def is_available(self, key: str) -> bool:
        """Unified check — key puede ser model name o provider name."""
        ...
    
    def record_success(self, key: str): ...
    def record_failure(self, key: str): ...
    def get_status(self) -> dict: ...
    def persist(self, path: Path): ...
    def load(self, path: Path): ...
```

### Mapeo de integración

| Funcionalidad actual | Origen | Destino unificado |
|---------------------|--------|-------------------|
| `_CIRCUIT_BREAKER.is_available(model)` | dsol.py (fachada) | `ether.circuit._ETHER_CIRCUIT_BREAKER.is_available(model)` |
| `_CIRCUIT_BREAKER.record_success(model)` | dsol.py (fachada) | `ether.circuit._ETHER_CIRCUIT_BREAKER.record_success(model)` |
| `_CIRCUIT_BREAKER.record_failure(model)` | dsol.py (fachada) | `ether.circuit._ETHER_CIRCUIT_BREAKER.record_failure(model)` |
| `_CIRCUIT_BREAKER.get_status()` | dsol.py (fachada) | `ether.circuit._ETHER_CIRCUIT_BREAKER.get_status()` |
| `get_breaker(provider)` | cost_opt.py | `ether.circuit.CircuitBreaker(...)` |
| `record_provider_result(p, success)` | cost_opt.py | `ether.circuit._ETHER_CIRCUIT_BREAKER.record_result(p, success)` |
| `provider_available(p)` | cost_opt.py | `ether.circuit._ETHER_CIRCUIT_BREAKER.is_available(p)` |
| `breaker_states` en `cost_optimizer.json` | cost_opt.py | `ether.circuit._ETHER_CIRCUIT_BREAKER.persist()` en `cache/circuit_breaker.json` |

### Migración (implementada)

```

Fase 3 (WP8):  lib/llm.py actualizado para usar ether directamente
Fase 4 (WP10): cost_optimizer.CircuitBreaker marcado como @deprecated

```

## Consecuencias

### Positivas
+ Single source of truth para circuit breaking en `lib/ether/circuit.py`
+ Semántica unificada: `is_available(key)` acepta tanto models como providers
+ Persistencia integrada (no solo en cost_optimizer.json)
+ Thread safety: estado protegido por threading.Lock
+ Tests unificados en `test_ether_router.py`
+ Dashboard puede mostrar estado de un solo breaker
+ Reduce líneas totales: 2 * ~40 líneas → ~60 líneas (ahorro ~20 líneas)

### Negativas
- Cambio de imports en `lib/llm.py` (riesgo bajo, WP8 con test coverage)
- `cost_optimizer.py` pierde su funcionalidad más crítica; podría deprecarse parcialmente
- Migración requiere mantener `lib/dsol.py` como fachada hasta KAOS v3.0
