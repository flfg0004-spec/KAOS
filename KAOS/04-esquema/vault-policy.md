# Vault Policy — OpenCode Memory System

## Ownership Zones

| Zone | Writer | Reader(s) | Autonomy Level |
|------|--------|-----------|----------------|
| `raw/` | Human only | Aletheia, Kosmos, Metis | Human-only |
| `schema/ADRs` | Kosmos (propose), Human (approve) | All agents | Human approves |
| `schema/KAOS.md` | Human only | All agents | Human-only |
| `schema/vault-policy.md` | Human only | All agents | Human-only |
| `wiki/entities/` | Metis (vault MCP) | All agents | Auto + flag |
| `wiki/concepts/` | Aletheia, Metis (vault MCP) | All agents | Auto |
| `wiki/sources/` | Aletheia (vault MCP) | All agents | Auto |
| `wiki/index.md` | Auto-generated by `_scripts/update-index.ps1` | All agents | Auto |
| `wiki/log.md` | All agents (append-only, vault MCP) | All agents | Auto |
| `_scripts/` | Kosmos (vault MCP) | All agents | Auto |
| `_pending/` | Agents (write), Human (review + resolve) | Human only | Deferred review |
| `_pipeline/` | All agents (update status, write output) | All agents | Auto |
| `cache/metadata.json` | Generated by hydrate | All agents | Auto |
| `schema/lint-report.md` | Auto-generated by `_scripts/lint-vault.ps1` | All agents | Auto |
| `schema/health-report.md` | Auto-generated by `_scripts/check-health.ps1` | All agents | Auto |

## Autonomy Levels

| Level | Description | Review Required |
|-------|-------------|-----------------|
| **Auto** | Agent writes directly, no review | None |
| **Auto + flag** | Agent writes directly, flags for deferred review | None (deferred) |
| **Human approves** | Agent proposes, waits up to 30 min for human response | Required (timeout auto-applies) |
| **Human-only** | Only humans modify | N/A |
| **Deferred review** | Change auto-applies, logged in `_pending/` | When human reviews |

## Obsidian Protocol

- Obsidian MCP is available for **human reading** of the vault.
- **Agents must NOT write to the vault via Obsidian MCP.** Only vault MCP (server-filesystem) is used for writes.
- Humans may edit `raw/` and `schema/` via Obsidian or any editor.
- If a human edits an agent-owned file (e.g., a concept), the agent will reconcile on next write.
- Git log provides full audit trail. Last-writer-wins with git history for rollback.

## Conflict Resolution

Since zones have exclusive writers, write conflicts should not occur by design.
If a conflict does occur (e.g., human edits an agent file):

1. Git identifies the conflict on next commit
2. Last commit wins (most recent timestamp)
3. The losing change is preserved in git history
4. A note is added to `log.md` documenting the conflict

## Human Absence Protocol

When the human does not respond to an "edit ask" within 30 minutes:

1. The change auto-applies (ADD-only: nothing is overwritten)
2. A record is written to `_pending/` describing the change
3. The change is logged in `log.md` as `auto-approved (timeout)`
4. The human can revert any auto-applied change via `git revert`

This prevents the system from blocking on human availability while preserving human oversight.

## Graceful Degradation

If any script fails (e.g., `update-index.ps1` crashes):

- `index.md` retains its previous version
- A warning flag `⚠️ Index may be stale` is added at the top
- The failure is logged in `log.md`
- The system continues operating with the stale index

## Vault Lifecycle

1. Agent starts session → `hydrate-context.ps1` loads context
2. Agent works → reads/writes vault as needed
3. Agent finishes → `extract-session.ps1` writes to `log.md`, triggers index rebuild, commits to git
4. Weekly → `lint-vault.ps1` scans for issues
5. Daily → `check-health.ps1` verifies integrity
